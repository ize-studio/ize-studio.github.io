제미나이와의 마지막 과제

2026년 6월 28일

English translation → 브런치 원문 ↗

제미나이는 나름 치밀하게 프로그램을 만들어 놓았었다. 하나의 C언어 파일에 한글과 영어, 독일어, 프랑스어, 터키어, 몬테네그로어를 모두 쓸 수 있는 프로그램의 뼈대를 만들어 놓은 것이었다. 헤더파일로는 한글 자모음을 조합하는 엔진 정도만 있을 뿐이었다. 그래서 그때는 메인 역할을 하는 아두이노 *.ino파일 하나와 한글 폰트가 들어 있는 헤더파일 하나, 한글 조합 엔진 헤더파일 하나, 이렇게 세 개로 모든 것이 이루어졌다.

글을 쓰다 보면 문제점이 하나씩 튀어나왔지만 그때그때 주먹구구식이라 해도 어찌어찌 해결해 나갔다. 아직까지 제미나이가 미처 생각지 못해서 적용하지 못한 부분이 있는 걸 당연하게 생각할 때였다. 어떤 때는 한 문서에 글자 수가 500자가 넘어가면 기기가 거의 멈추다시피 하기도 했고, 어떤 때는 글의 첫 부분으로 갔다 오면 그다음부터는 화면의 맨 아랫줄만 정상적으로 표시되기도 했다. 그래도 차례로 함수들을 들여다보며 제미나이의 설명을 보면서 하나씩 수정해 나갔다.

모든 것이 완성되고 말 그대로 남들에게도 ‘이 정도면 완성되었다고 할 수 있지 않을까?’ 하고 말할 수 있을 정도가 되었을 때, 레딧에 화면을 찍은 사진과 동영상을 올렸다. 깃허브에 코드를 공개한 것도 그때였다. 아두이노 IDE로 작성한 코드였다는 것 외에는 아무것도 몰랐던 나는 환경이나 이런 건 모두 생략하고 저 파일 세 개만 달랑 올려놓고 끝났긴 했지만. 아마도 그때는 코드를 설명하는 readme.md파일도 작성하지 않았을 것이다. 작성 요령조차 Visual Studio Code에 코덱스와 클로드를 연동하고 나서야 알게 되었기 때문이다.

이때, 하나의 욕심을 부렸다. 이후에 세상의 모든 언어라는 새로운 목표를 세우기는 했지만 그전에, 제미나이와 아두이노 IDE만 사용할 때까지는 그렇게 거창한 목표는 세울 수 없었다. 그냥 소박하게 메인 파일이 너무 크고 함수들이 집중되어 있으니 일단 나부터 차근차근 보면서 공부할 수 있게 좀 기능별로 함수들을 분산시킨, 더 많은 헤더파일과 더 작은 메인 파일의 구조로 바꾸어 보자는 것이었다.

그때까지 완성된 코드의 모습은 다음과 같았다.

화면에 글자를 아랫줄부터 채우면서 화면 끝에 도달하면 자동으로 줄 바꿈 해주는 기능 있음

텍스트파일 생성 기능 있음

저장하는 기능 있음

방향키로 커서를 이동하는 기능 있음

백스페이스로 현재 커서의 위치에서 앞쪽으로 글자를 지워 나가는 기능 있음

한글, 외국어 조합과 컨트롤+스페이스바 조합으로 전환하는 가능 있음

컨트롤 +F 조합으로 찾기 기능 있음

컨트롤+L조합으로 잠자기 기능 있음

컨트롤+방향키로 단어 간 이동 기능 있음

컨트롤+백스페이스 키로 단어 단위로 지우는 기능 있음

메뉴에서 글자 크기, 글자 간격, 잠자기 대기 시간 등 조정할 수 있음

메뉴에서 한국어만 고정이고 나머지 언어들(영어, 프랑스어, 독일어, 터키어, 몬테네그로어) 중 선택할 수 있음

이때 네트워크 기능이 있었던 것 같기는 한데 정확한 기억은 잘 나지 않는다. 이때인지 이 이후인지 모르겠지만 블루투스 모드를 켜서 이 기기를 블루투스 외장 키보드로 사용하게 했던 적이 있기는 했다. 웹서버 역할을 하게 해서 와이파이 모드에서는 다른 기기에서 이 기기에 접속을 한 상태로 글을 보게 한 적도 있는데, 이때 Network.h파일이 있던 걸로 봐서는 둘 중 하나 이상은 구현을 했던 것 같다. 어쨌든 프로그램의 모습이라는 게 저런 리스트라는 건, 처음부터 계획을 짜서 만들어낸 게 아니라 저 기능들을 하나하나 덕지덕지 붙여 나간 것이라는 뜻이었다. 그러니까 메인 코드에서는 함수들을 불러다 조합하면서 돌게하고 함수의 본체들은 종류별로 모아놓자는 건 이제 한번 전체적으로 구조를 짜보자는 의미에 다름 아니었다.

하지만 결론은 실패였다. 제미나이가 코드를 보지 못하는 상태에서는 변수 이름이나 함수 이름, 심지어 함수의 매개변수 이름조차 틀리기 일쑤였다. 파일을 올려도 절대 읽지 않았다. 계속해서 내게 틀리게 알려주고 그런 변수가 없다고 이야기를 하면 ‘일반적인 그런 이름의 함수는 그렇게 사용했기에 잘 몰랐다’는 대답만 돌아왔다. 결국 한 3일 정도를 그렇게 허비한 끝에, 파일 분리는 포기하기로 결정했다. 파일을 통째로 올려도 크레딧 소모하는 속도만 빨라질 뿐 다를 건 전혀 없었다. 코드를 복사해서 올려도, 코드 파일 그대로 올려도 보지 않고 대답하는 건 매한가지였다.

그 뒤로 일주일 정도는 폰트를 바꾸어 가며 실험을 했다. 어떤 글씨체도 마음에 들지 않았는데, 그렇다고 깃허브에 공개하지도 못하는 폰트를 사용하고 싶지는 않았다. 영상도 찍고 사진도 찍어서 올려놓고 누군가 “그런 한글 모습이라면 저도 써보고 싶네요”라고 말하는데 거기다 대고 알아서 헤더 파일을 만들어 쓰라고는 할 수 없었던 것이었다. 그래서 찾아낸 것이 둥근모체였긴 했지만, 영문 폰트와 너무 달라서 어울리는 가는 글씨체를 찾으려고 헤맸다. 제미나이와 그냥 그만해야겠다고 생각한 계기가, 다른 부분에서도 그렇긴 했지만 폰트에서도 이랬다 저랬다 하면서 그냥 이 글씨체를 쓰는 편이 낫겠다느니, 더 찾아보겠다느니 하는 반복이 큰 역할을 했다. 몇 번이고 없는 글자가 생기거나 한글을 하나도 표시하지 못하거나 심지어 상태표시줄의 가로줄 말고는 화면에 아무것도 표시할 수 없기도 했지만, 화를 내면서 되돌리고 다시 폰트를 만들다 보면 갑자기 해결책을 찾았다고 하는데, 그 해결책이 둥근모체를 사용하는 것이라는 말을 한 게 서너 번은 되었던 것 같다.

그래서 결국, 더 큰 프로젝트를 하기 위해서는 다른 방법을 찾아야겠다고 생각을 했는데, 그때 마침 와이프가 ‘요즘 클로드가 뜨고 있다는데, 클로드는 처음부터 코딩에 특화되어 있다고 하더라.’라는 말을 했다. 인터넷 검색을 해보니 이미 많은 사람들이 클로드와 코덱스를 사용하고 있었다. 코덱스는 그때 처음 들었기에 일이 있어서 외출했다가 한두 시간 아무것도 하지 않고 기다려야 할 시간이 생겨 블로그들을 자세히 읽어 보니 클로드는 Visual Studio Code에 설치해서 사용할 수 있다고 했다. 심지어 코덱스는 모바일로는 사용이 불가능한데 Visual Studio Code에 연동이 된다고 했다(지금은 모바일로 사용할 수 있지만 PC에 설치된 버전이 서버 역할을 해야 한다.). PC로만 사용할 수 있다면 연동하는 편이 낫겠지 싶었다. 마침 제미나이와 파일 분리를 위해 머리를 싸매고 고민할 때, 빌드가 되는지 테스트하는데 너무 오래 걸려서 빌드 시간 단축을 위해서 기존의 아두이노 코드를 Visual Studio Code에 이식하고 정상적으로 빌드하고 업로드하는 단계까지 구현해 놓은 상태였다.

계속해서 파일 분리 시도가 실패만 거듭하고 있었기 때문에 긴가민가 하면서 제미나이를 반쯤 의심하며 제미나이가 하라는 대로 설치하고 설정을 하긴 했지만 정말로 아두이노 IDE에서 하던 똑같은 일이 Visual Studio Code에서는 1/3 정도의 시간밖에 걸리지 않았다. 과거에 제미나이가 이상한 코드를 주어도 에러를 확인하는 데 5분 가까이 걸렸다면 새로운 환경에서는 80초 정도면 끝났다. 어떤 차이 때문이라고는 했지만 당시에도 이유에는 관심이 없었고 지금도 거기까지 관심이 가지는 않는다. 앞으로도 그냥 Visual Studio Code에서 해야겠다는 생각뿐. 그러고 보니 제미나이 확장 라이브러리도 있었는데 사용하지 않았다. 왜였는지는 모르지만 추천이 떴는데도 닫아버렸던 기억은 난다. 아마도 그 확장을 사용했다면 아주 조금 오래 사용했을 것 같기는 하다.

그 뒤에, 그러니까 하루의 고민 후 나는 클로드와 코덱스, 둘 중 어떤 것도 우열을 가릴 수 없기에 그 둘을 모두 결제했다.

그리고 정말 말 그대로 새로운 장이 열렸다.

가끔은, 타건 소리가 끌릴 때가 있어 키보드 영상을 틀어놓곤 하는데 내 글을 쓰는 소리는 어떨까 궁금하기도 했지만 녹화를 한다는게 글쓰기에 방해가 되지 않을까 싶어 주저해오다가 마침내 “내가 만든 펌웨어로 쓰는 글”이라는 타이틀의 유혹이 너무나도 커서 시도해 보았습니다.
